# mind

Движок «сознание + подсознание» на одном корпусе: логи саппорта Ubuntu IRC
(`data/ubuntu_dialogs/`, ~1.85 млн файлов, ~100 млн слов). Корпус лежит в
`data/` и не попадает в git.

## Запуск

```bash
cargo run --release                      # стадия + чекпоинт-путь + чат
cargo run --release -- --minutes 0       # без ограничения по времени
cargo run --release -- --no-chat         # без интерактивного чата
```

Режим `release` обязателен: debug-сборка примерно в 6 раз медленнее.

Опции:

| опция | смысл |
|---|---|
| `--steps N`        | сколько токенов показать вживую в начале стадии (600) |
| `--minutes N`      | бюджет стадии в минутах; **0 = без ограничения** (1) |
| `--ubuntu-files N` | обработать только N файлов (0 = все) |
| `--ubuntu-sample N`| файлов для IDF-модели промптов (4000) |
| `--max-mb N`       | остановить обучение, если процесс превысил N МБ RAM (0 = без лимита) |
| `--ram N`         | бюджет памяти движка в ГБ (8; можно дробно, напр. 0.4; 0 = без бюджета) |
| `--save <файл>`    | сохранить состояние движка и позицию в корпусе |
| `--load <файл>`    | продолжить с сохранённого состояния |
| `--delay N`        | пауза между токенами живого вывода, мс (20) |
| `--max-reply N`    | максимум токенов в ответе чата (24) |
| `--no-chat`        | не входить в чат |

## Стадия

Одна общая стадия на корпусе: движок читает логи по одному файлу, учится
продолжать каждую реплику и печатает первые токены вживую — с цветом от
красного (шаг плохой) к зелёному (шаг хороший) и блоком `[f=.. q=.. t1=.. t3=..]`.
Дальше идёт построчный прогресс: `files 12345/1850268 (0.7%), eta 41m`, рядом
`t1/t3`, `reach` (потолок для t1/t3) и расход памяти.

## Память

Корпус читается по одному файлу — в RAM лежит только текущий файл и
статистика (сырые токены не хранятся). Отдельной карты частотностей больше
нет: словарь собирается из самих таблиц движка (`tokenFrequencies`), поэтому
в процессе не растёт ни одна лишняя структура.

Замер: 10 000 файлов за 47 с → 760 МБ; полный корпус за те же 61 с
→ 830 МБ. RAM зависит от числа шагов, а не от размера корпуса, значит корпус
действительно не держится в памяти.

### Бюджет `--ram`

Губернатор меряет **размер самих таблиц** (`строки × записи`, 512 Б на строку
и 96 Б на запись), а не RSS процесса: цифра не зависит от аллокатора и
одинаково трактуется для подсознания и сознания.

- как только таблицы вышли за половину бюджета, лимит строк снижается и
  самые слабые строки вытесняются;
- **пол** — 10% бюджета (минимум 1000 строк): ниже него лимит не опускается,
  движок никогда не теряет память целиком;
- если прошлая чистка **не снизила** размер таблиц, лимит больше не
  сжимается — иначе движок только ужимал бы себя впустую;
- при запасе лимит расширяется, и движок снова запоминает больше.

В прогрессе видно обе цифры: `tables 812/2048Mb, rss 1010Mb`.

### Что вытесняется

Строки делятся на три группы, и вытесняются по порядку:

1. **брошенные** — их не использовали дольше 4 окон (окно = 20000 шагов);
2. **закреплённые** (`hits ≥ 3`) — слабейшие первыми;
3. **свежие** — последние, у них есть шанс закрепиться.

Свежая строка защищена, пока есть кого вытеснить: без этого новое никогда
не закрепилось бы, и движок замер бы на том, что выучил в начале корпуса.
Сила строки (`hits`) затухает на 10% за окно, если строку не используют, —
старые знания слабеют, новые их обгоняют.

У сознания вес рёбер одного признака тоже ограничен (кап 24): слабые
продолжения подрезаются, а список лучших продолжений пересобирается.

Пример: `--ram 2` → 1315 МБ в процессе, top1 15.3% / top3 25.5%.

## Чанки и чекпоинты

Корпус большой, состояние движка растёт, поэтому обучение можно резать на
чанки: каждый запуск читает состояние, отрабатывает своё время и сохраняет
состояние на диск.

```bash
# первый чанк: обучение + сохранение
cargo run --release -- --minutes 10 --save mind.bin

# следующий чанк: продолжение с места
cargo run --release -- --minutes 10 --load mind.bin --save mind.bin
```

`--load` пропускает разогрев и продолжает ровно с того файла, на котором
остановились; статистика и позиция корпуса накапливаются в чекпоинте.

Формат чекпоинта версионируется (сейчас версия 2: в строках и рёбрах
хранятся счётчики `uses` и эпоха). Чекпоинт старой версии не подойдёт —
движок честно скажет `unsupported checkpoint version`, обучение придётся
начать заново.

Полный корпус можно запустить одним процессом: `--minutes 0` снимает потолок
по времени, а `--ram` держит память в узде. В прогрессе и в итоговом отчёте
есть ETA до конца корпуса (файлы/с × остаток).

## Метрики

`t1`/`t3` — доля шагов, где истинный токен оказался первой/в первой тройке
предложений. `reach` — доля шагов, где истинный токен вообще попал в набор
кандидатов: это потолок для `t1`/`t3`, и он важнее самих процентов.

## Формат корпуса

`data/ubuntu_dialogs/dialogs/<группа>/<файл>.tsv`, строки вида
`время \t ник \t получатель \t текст`. Реплики одного ника подряд склеиваются
в один ход, ход обрезается на 40 токенов.
