# mind

Движок «сознание + подсознание» поверх трёх корпусов: cmake-документы (`data/`),
диалоги DailyDialog (`data2/ijcnlp_dailydialog/`) и логи саппорта Ubuntu IRC
(`data2/ubuntu_dialogs/dialogs/`).

## Запуск

```bash
cargo run --release                      # всё: фаза 1 -> 2 -> 2b -> 3 -> чат
cargo run --release -- --minutes 30      # долгая фаза на Ubuntu-логах
cargo run --release -- --no-chat         # без интерактивного чата
```

Режим `release` обязателен для длинных прогонов: debug-сборка примерно в 6 раз
медленнее.

Опции:

| опция | смысл |
|---|---|
| `--steps N`        | шагов live-вывода фазы 1 (600) |
| `--limit N`        | сколько диалогов DailyDialog взять из train (0 = весь сплит) |
| `--minutes N`      | бюджет фазы Ubuntu в минутах (1; 0 = пропустить) |
| `--ubuntu-sample N`| файлов Ubuntu-логов для IDF-модели промптов (4000) |
| `--max-mb N`       | остановить обучение, если процесс превысил N МБ RAM (0 = без лимита) |
| `--delay N`        | пауза между шагами live-вывода, мс (20) |
| `--max-reply N`    | максимум токенов в ответе чата (24) |
| `--no-chat`        | не входить в чат |

## Фазы

1. **docs** — тот же live-поток, что и раньше; блок `[...]` красится от зелёного
   к красному по качеству текущего шага (`q=`), рядом `t1/t3` по следующему токену.
2. **dialogues** — DailyDialog: классификатор актов (inform/question/directive/
   commissive) и генератор ответа.
2b. **ubuntu** — потоковое обучение на логах Ubuntu IRC (`ts \t nick \t target \t
   message`), 1.85 млн файлов читаются по одному, бюджет по времени.
3. **eval** — метрики на официальном test-сплите DailyDialog и на отложенной
   части Ubuntu-логов.
4. **chat** — пишете строку, Enter, модель отвечает. Команды: `/quit`, `/help`,
   `/stats`, `/top`, `/act <1-4>`.

## Метрики

`t1`/`t3` — доля шагов, где истинный токен оказался первой/в первой тройке
предложений. `reach` — доля шагов, где истинный токен вообще попал в набор
кандидатов: это потолок для `t1`/`t3`, и он важнее самих процентов.

## Разделение признаков

Признаки docs-корпуса остались байт-в-байт прежними (`prev:`, `pair:`, `prev2:`).
Диалоговые изолированы префиксами, чтобы не портить обученную модель:
`a:*` — акты, `bag:`/`mode:reply`/`act:` — генерация ответа.
