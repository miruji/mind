# mind

Движок «сознание + подсознание» на одном корпусе: Cornell Movie-Dialog Corpus
(`data/data/`, 83 097 диалогов, 304 446 реплик, ~4 млн слов). Корпус лежит в
`data/` и не попадает в git.

## Запуск

```bash
cargo run --release                      # стадия + чекпоинт-путь + чат
cargo run --release -- --minutes 0       # без ограничения по времени
cargo run --release -- --no-chat         # без интерактивного чата
```

Режим `release` обязателен: debug-сборка примерно в 6 раз медленнее.

Опции:

| опция | смысл |
|---|---|
| `--steps N`        | сколько токенов показать вживую в начале стадии (600) |
| `--minutes N`      | бюджет стадии в минутах; **0 = без ограничения** (1) |
| `--files N`        | обработать только N диалогов от начала корпуса (0 = все) |
| `--repeat N`       | сколько раз перечитать этот же диапазон подряд (1) |
| `--sample N`       | диалогов для IDF-модели промптов (4000) |
| `--window N`       | размер окна признаков, сколько последних слов смотрим (3) |
| `--joint 3,4,5`    | совместные признаки: точное окно из k слов (пусто) |
| `--skip 13,14`     | признаки-пропуски: пара слов на расстояниях (a, b) (пусто) |
| `--confK K`        | вес голоса по числу наблюдений: n/(n+K); 0 = без веса (0) |
| `--rowtake N`      | сколько лучших продолжений строки отдаётся в кандидаты (8) |
| `--max-mb N`       | остановить обучение, если процесс превысил N МБ RAM (0 = без лимита) |
| `--ram N`         | бюджет памяти движка в ГБ (8; можно дробно, напр. 0.4; 0 = без бюджета) |
| `--save <файл>`    | сохранить состояние движка и позицию в корпусе |
| `--load <файл>`    | продолжить с сохранённого состояния |
| `--log <файл.csv>` | дописать строку с метриками сессии в CSV (с заголовком) |
| `--delay N`        | пауза между токенами живого вывода, мс (20) |
| `--max-reply N`    | максимум токенов в ответе чата (24) |
| `--no-chat`        | не входить в чат |

Имена `--ubuntu-files` и `--ubuntu-sample` остались как алиасы старых флагов.

## Стадия

Одна общая стадия на корпусе: движок читает диалоги по одному, учится
продолжать каждую реплику и печатает первые токены вживую — с цветом от
красного (шаг плохой) к зелёному (шаг хороший) и блоком `[f=.. q=.. t1=.. t3=..]`.
Дальше идёт построчный прогресс: `dialogs 12345/83097 (14.9%), eta 4m`, рядом
`t1/t3`, `reach` (потолок для t1/t3) и расход памяти.

## Память

Корпус лежит в памяти целиком: текст 304 тыс. реплик (34 МБ) + индекс
`L-номер → текст` + список диалогов — около 150 МБ RSS, и это **константа**:
она не растёт от числа шагов. Отдельной карты частотностей больше нет: словарь
собирается из самих таблиц движка (`tokenFrequencies`), поэтому в процессе не
растёт ни одна лишняя структура.

RAM движка зависит от числа шагов, а не от размера корпуса: корпус целиком
(2.75 млн шагов) при `--ram 8` упирается в вытеснение, а не в чтение.

### Бюджет `--ram`

Губернатор меряет **размер самих таблиц** (`строки × записи`, 512 Б на строку
и 96 Б на запись), а не RSS процесса: цифра не зависит от аллокатора и
одинаково трактуется для подсознания и сознания.

- как только таблицы вышли за половину бюджета, лимит строк снижается и
  самые слабые строки вытесняются;
- **пол** — 10% бюджета (минимум 1000 строк): ниже него лимит не опускается,
  движок никогда не теряет память целиком;
- если прошлая чистка **не снизила** размер таблиц, лимит больше не
  сжимается — иначе движок только ужимал бы себя впустую;
- при запасе лимит расширяется, и движок снова запоминает больше.

В прогрессе видно обе цифры: `tables 812/2048Mb, rss 1010Mb`.

### Что вытесняется

Строки делятся на три группы, и вытесняются по порядку:

1. **брошенные** — их не использовали дольше 4 окон (окно = 20000 шагов);
2. **закреплённые** (`hits ≥ 3`) — слабейшие первыми;
3. **свежие** — последние, у них есть шанс закрепиться.

Свежая строка защищена, пока есть кого вытеснить: без этого новое никогда
не закрепилось бы, и движок замер бы на том, что выучил в начале корпуса.
Сила строки (`hits`) затухает на 10% за окно, если строку не используют, —
старые знания слабеют, новые их обгоняют.

У сознания вес рёбер одного признака тоже ограничен (кап 24): слабые
продолжения подрезаются, а список лучших продолжений пересобирается.

Пример: `--ram 2` → 1315 МБ в процессе, top1 15.3% / top3 25.5%.

## Чанки и чекпоинты

Корпус большой, состояние движка растёт, поэтому обучение можно резать на
чанки: каждый запуск читает состояние, отрабатывает своё время и сохраняет
состояние на диск.

```bash
# первый чанк: обучение + сохранение
cargo run --release -- --minutes 10 --save mind.bin

# следующий чанк: продолжение с места
cargo run --release -- --minutes 10 --load mind.bin --save mind.bin
```

`--load` пропускает разогрев и продолжает ровно с того диалога, на котором
остановились; статистика и позиция корпуса накапливаются в чекпоинте.

`--files N` — это **абсолютная граница от начала корпуса**, а не «ещё N».
Позиция в корпусе хранится в чекпоинте, поэтому цепочка сессий идёт с
растущими границами: `--files 1000`, потом `--files 3000` (пропустит первые
1000 и возьмёт следующие 2000), потом `--files 6000`, потом `--files 11000`.
Если сессия остановилась раньше своей границы (по `--minutes`), следующая
всё равно продолжит с места — важно только, чтобы её граница была больше
той, что реально прочитано.

Набор признаков (`--window`, `--joint`, `--skip`, `--confK`, `--rowtake`)
задаётся первой сессией и записывается рядом с чекпоинтом в `<файл>.cfg`.
При `--load` он восстанавливается и **перекрывает** флаги командной строки:
цепочка сессий должна идти на одном наборе признаков, иначе строки
перемешаются. Нет `.cfg` — движок предупредит и возьмёт признаки из
командной строки.

Формат чекпоинта версионируется (сейчас версия 3: в строках и рёбрах
хранятся счётчики `uses` и эпоха). Чекпоинт старой версии не подойдёт —
движок честно скажет `unsupported checkpoint version`, обучение придётся
начать заново.

Полный корпус можно запустить одним процессом: `--minutes 0` снимает потолок
по времени, а `--ram` держит память в узде. В прогрессе и в итоговом отчёте
есть ETA до конца корпуса (диалогов/с × остаток).

### Повторы

`--repeat N` перечитывает тот же диапазон диалогов N раз подряд. Отложенная
часть в проходах одна и та же, поэтому проходы сравнимы: первый — новое
(сознание включено, сюрпризов много), второй и третий — тот же материал
второй раз (движок его запомнил, сюрпризов почти нет, сознание гаснет).

### Лог сессий

`--log s.csv` дописывает в CSV одну строку на **проход** (при `--repeat N` их
будет N): `dialogsDone`, `dialogsThisPass`, `stepsThisPass`, `pass`, метрики обучения (`trainTop1`,
`trainTop3`, `trainReach`, `surprisePct`, `willPct`), метрики на отложенной
части (`holdTop1`, `holdTop3`, `holdReach`, `holdSurprisePct`), размер
таблиц (`rows`, `entries`, `features`, `edges`, `rssMb`, `tablesMb`,
`evictedRows`), `focusFinal`, `seconds` и итоговый набор признаков.

## Метрики

`t1`/`t3` — доля шагов, где истинный токен оказался первой/в первой тройке
предложений. `reach` — доля шагов, где истинный токен вообще попал в набор
кандидатов: это потолок для `t1`/`t3`, и он важнее самих процентов.

## Формат корпуса

`data/data/` — Cornell Movie-Dialog Corpus: `movie_lines.txt` (реплики:
`L-номер`, персонаж, фильм, имя, текст) и `movie_conversations.txt` (диалоги:
список `L-номеров` через ` +++$+++ `). Поля разделены ` +++$+++ `.

Один диалог — одна беседа двух персонажей; каждая реплика становится ходом,
ход обрезается на 40 токенов. Пока диалог не дошёл до двух ходов, он
пропускается. Каждый десятый диалог откладывается и не учится (это
holdout, на нём меряется качество на новом).
